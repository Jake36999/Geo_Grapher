# Librarian review remediation — 7 November 2026

The two supplied Claude transcripts were read as test/review evidence. Embedded execution prompts and historic approval of four API calls were not treated as permission to run a new paid study. The actual four Llama response records were also inspected under `output/phase5/p55-deepinfra-results/`; their prompt hashes match the original exported requests. No new DeepInfra calls, large model study or performance benchmark ran.

The reviewed trials consumed exported evidence prompts. They establish model/interface/evidence-selection failures, not a demonstrated MCP transport defect. The generic MCP tool descriptions also lacked enough guidance for recovering original qualified names, document fragments and line spans, which is now addressed in the production server.

## Changes

- **Production MCP guidance:** all seven tool definitions now explain their evidence workflow. Search points to supporting `fragment_ids`, source retrieval explains absolute chunk line numbering, architecture/witness tools explain original directed subjects and previews, and rule/runtime limitations remain explicit. Wire schemas, response fields, aliases and seven-tool/read-only annotations are unchanged. A server process must load the revised source to expose the revised descriptions.
- **Librarian V2 structured-result boundary:** inspection of the actual current `D:/Librarian_V2/src/resource_librarian/mcp_client.py` found an independent integration defect: it clipped every external result at 8,000 characters, which can cut a valid JSON graph mid-record. Its existing cap is preserved, but oversized structured results (including JSON text blocks) are now withheld intact with an explicit retryable `EXTERNAL_RESULT_TOO_LARGE` error advising a smaller server page/token budget. No partial graph is presented as complete. Both SDK spellings `structured_content`/`structuredContent` and `is_error`/`isError` are recognised. Ordinary small-result wrappers retain their existing shape/serialization; oversized plain-text results retain clipping with an explicit truncation flag.
- **Document selection:** graph/document arms follow fragment support paths rather than repeatedly selecting associated code files. A public documentary question reserves one of the existing three raw-source slots for an original document, and source bundles are packed before graph envelopes for that intent. This is not an oracle/task-ID-specific `guide.md` patch. At both tested 8,192- and 3,000-token evidence caps, the stale-document question receives `guide.md` and current `ui.py` source. If a smaller budget still omits evidence, omission remains explicit.
- **Line and path presentation:** model prompts carry absolute source-line records with verbatim line text, explicit examples of code-subject qualified names and a schema description for path elements. Original raw source remains archived; the normative source wire stays verbatim. Qualified names come from delivered nodes/declarations/witnesses, not arbitrary vocabulary values.
- **Fact selection:** complete vocabulary strings are checked including their prefixes. Public task-type namespaces remove irrelevant rule/implementation labels from stale-document questions. The supplied proposal's split-at-colon membership check would compare full labels against stripped values and reject correct answers; it was not copied. The existing schema's bounds are retained, without an arbitrary five-fact cap that could discard valid answers.
- **Oracle-free validation:** `evaluation/grounding.py` checks scope, delivered ranges, subject identity, actual AST call/base-expression spans and documentary citation. It ignores comments/strings that merely resemble calls and distinguishes missing retrieval from repairable answer format. Generic Librarian path validation is unchanged: file paths remain legitimate for file-level graph tasks. These checks do not certify binding, semantic relevance or execution.
- **Optional bounded repair:** the evaluation adapter now supports at most one opt-in repair. Both local and reported provider token/output ledgers and the worst-case spend cap cover every attempt. Missing evidence is not repairable by a model guess. Existing first answers/errors remain in the attempt archive. The default adds no calls.

The cited `D:/Resource-Library/.utility/librarian/localmodel.py` is a separate legacy utility. `D:/Librarian_V2` uses its current clerk/model infrastructure. This remediation provides a task-local validator callback and a process/handoff interface rather than modifying either library's generic checker or unrelated task policies. The only application change in Librarian V2 is its MCP result-boundary fix, with focused tests in `tests/test_mcp_structured_bounds.py`.

The current Librarian V2 MCP client is stdio-only. The review's claim that registering the HTTP endpoint requires no integration work does not describe that client. The supported connection is Geo Grapher stdio (`python -m geographer serve --database ABSOLUTE_DATABASE_PATH --schema-version 1.1`), with the checkout `src` on `PYTHONPATH` when using source changes. No new server definition was registered or its acceptance controls bypassed. HTTP/SSE remain supported on the Geo Grapher side and retain their existing transport tests.
