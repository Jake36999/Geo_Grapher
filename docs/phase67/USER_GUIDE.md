# Using the Phase 6–7 workspace

Open the served workspace and choose an **Active graph**. Check additional graphs to compare them in the same display. Display composition keeps their analysis domains separate; nearby objects and matching labels do not establish equivalent code or execution paths. Labels, role badges, directional edge styling and discovery cards help orient you; open source and witnesses for evidence.

## Directed grouping

In the spatial view, choose atomic grouping and exact static relationships. The QI selector offers **Off**, **Helper balls** and **Directed**. Other grouping or relationship settings disable QI with an explanation.

Directed mode displays a certificate and block count. “Reachability preserved (existential)” means a connection between blocks is supported by reachability between at least some original members. It does not mean every member reaches every other member, that all members are interchangeable, or that a grouped cycle proves a leaf-level execution cycle. Inspect original directed witnesses for those questions.

Open the visible block list and expand a block to expose its members. Expansion is temporary; switching QI Off restores the atomic partition. Helper balls use the undirected distance certificate instead. Scene geometry and grouping never rewrite source containment or dependency facts.

## Bridge review

Select the intended graph pair, open **Bridge review**, and find candidates. A candidate is a scored suggestion, not an established relationship. Accept or reject it with a rationale. Only acceptance creates a bridge; rejected proposals remain decisions rather than edges. Repeating an already decided proposal is refused.

Inspect the bridge's current lineage state when its source snapshots change. An accepted historical declaration is not a guarantee that its supporting premises are still current. The proposed stricter homonym firewall is still an owner decision; it has not been silently enabled.

## Prune by derivation

Use box selection and the prune workflow to exclude a small source region. The operation creates a derived graph with its own provenance and profile. It leaves the source graph's snapshot unchanged. Verify the derived label and source link before continuing; deleting a graph is a different operation and requires confirming its label.

## Add folder

Open **Add folder**, browse within the roots allowed by the server's `--browse-root` options, and preview the proposed partitions. Untick unwanted partitions before starting ingestion. Follow the job's running/done/failed state; a preview is not an ingestion receipt.

No browse roots means the picker is disabled. Outside paths, traversal and junctions are refused. If a folder changes after preview, preview again. A preview cannot authorise a path that later becomes unavailable or a junction.

## Drift and cross-graph evidence

Drift compares immutable snapshots using stored fingerprints and explicit evidence. Read the tier and its supporting fields; UNKNOWN is not a claim of equivalence or a broken contract. Reports distinguish changes to text, signature, body, guards and dependency structure.

Cross-graph analysis requires explicit graph selection. Evolution diffs and clone candidates help locate changes and similarities; bridge impact and theory conformance use their own declared premises and models. Start large reports with counts and filters, then page the evidence. Separate rankings from different graphs are not a universal relevance score, and an accepted bridge is not proof of semantic identity.

The owner’s [20-minute checklist](../../reports/PHASE67_WAVE4_GATE.md) remains the hands-on acceptance step. Automated browser evidence does not substitute for that sign-off.
