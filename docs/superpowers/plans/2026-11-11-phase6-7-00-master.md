## Part B — Formal definitions (normative)

These definitions fill the gaps the Gemini specs left, or replace definitions
they got wrong. Each item names the Gemini defect it fixes.

### G1. Contract evolution rule

*Fixes:* the specs edited frozen contracts and put hashes on the wire.

- **Per-snapshot derived data** has two homes:
  - (a) `analysis_results` rows with a new `algorithm_version`, for data read
    whole;
  - (b) a supplementary table from an addendum DDL file, for data that needs
    indexes.
- Supplementary fact tables (written before `publish`) join the immutability
  triggers.
- Derived caches written after `publish` (labels, layouts, discovery cards) do
  not join the triggers. They are keyed by `(snapshot_id, …, algorithm_version)`
  and are reproducible from facts.
- **Absence semantics:** a reader that finds no addendum table or no rows for a
  snapshot returns the explicit status `not_computed`.

### G2. Entity fingerprints (`entity-fingerprint-v1`)

*Fixes:* the specs never defined how hashes are computed, and their re-extractor
would have produced incompatible values.

Fingerprints are defined for entities of kind `function`, `method` and `class`
with a source span; every other kind gets NULL. All digests are
`sha256(canonical(value))` in lowercase hex, using `geographer.model.canonical`.

| Field | Value hashed |
|---|---|
| `span_sha256` | `sha256` of the raw bytes of lines `start_line..end_line` inclusive, taken from the file's `source-bytes-v1` bytes, with line endings as stored. |
| `ast_body_hash` | Existing py-ast-v1 value from `entities.ast_body_hash`, copied unchanged. NULL for classes. |
| `signature_hash` | `["sig-v1", header, decorators]`, where `header` is the existing `declaration-v1` `result.signature` string and `decorators` is the ordered list of `ast.unparse(d)` for `node.decorator_list`. |
| `ts_guard_hash` | `["guard-v1", clauses]`, where `clauses` is the pre-order list over the entity's own body (not nested defs or classes) of `[clause_kind, ordinal, guard_repr]`. `clause_kind ∈ {if, elif, while, for_iter, assert, match_case_guard, ifexp, comp_if, except_type, with_item}`. `ordinal` counts clauses per kind from 0. `guard_repr = ast.dump(expr, annotate_fields=False, include_attributes=False)` after renaming every `ast.Name` bound in the entity's own scope (per `ScopeIndex`) to `v<k>` in first-occurrence order. Free and global names are kept. |
| `exact_out_edges_hash` | `["out-v1", sorted([target_subject_id, subtype, sorted(reason_codes)])]` over relationships with `source_subject_id = e`, `family='static'` and `resolution_status='exact'`. `reason_codes` = sorted union of `reason_code` and `additional_reason_codes` across the relationship's evidence `details_json` (empty list if none). |
| `wl_3hop_hash` | Existing directed-wl3-v1 value, copied unchanged. |

`signature_hash` and `ts_guard_hash` are computed in `extract.py`, where the AST
nodes live (`self.definition_nodes`). The other fields are computed in
`analysis.prepare_analysis`, which runs on both ingest and merge.

### G3. Cross-snapshot entity identity and the drift classifier

*Fixes:* the specs assumed `entity_id` is stable across snapshots and gave a
tier table with a contradictory Tier 3.

**Identity resolution.** For an entity `e` in base snapshot `S_b`, its
counterpart in `S_n` is found by the first rule that applies:
- (i) the same `entity_id`;
- (ii) the unique entity in `S_n` with the same `(repo_id, qualified_name, kind)`;
- (iii) the unique entity in `S_n` with the same `(repo_id, kind, ast_body_hash)`
  where that hash is unique in both snapshots. This case is classified `MOVED`.

If no rule applies, the outcome is `MISSING`.

**Drift tier.** Evaluate the conditions in this order and take the first match.
*(Amended in wave 2, ruling W2-5. In the original order, tier 4 could never be
reached: an entity whose own bytes are unchanged matched tier 0 or 1 first.)*

| Order | Tier | Condition (base → new) |
|---|---|---|
| 1 | — `MISSING` | no counterpart |
| 2 | — `UNKNOWN` | either side has no fingerprint row (G1 absence) |
| 3 | — `MOVED` | the counterpart was found by rule (iii), a unique `ast_body_hash` |
| 4 | 5 `CONTRACT_CHANGE` | any of `signature_hash`, `ts_guard_hash` or `exact_out_edges_hash` differs |
| 5 | 3 `BODY_REFACTOR` | different `ast_body_hash` |
| 6 | 2 `COSMETIC` | different `span_sha256` |
| 7 | 1 `LINE_SHIFT` | different `start_line` |
| 8 | 4 `NEIGHBOUR_DRIFT` | different `wl_3hop_hash` |
| 9 | 0 `IDENTICAL` | otherwise |

When a span change and neighbour drift coincide, `COSMETIC` wins, so quoted
spans re-anchor.

**Outcome matrix.** Each premise names one invariance contract. The outcome is one
of `NOOP`, `REANCHOR`, `SUSPECT`, `HARD`, `UNKNOWN`:

| Tier \ contract | STRICT_BYTE_SPAN | AST_ALPHA_INVARIANT | CONTROL_GUARD_INVARIANT | TOPOLOGICAL_WL3 |
|---|---|---|---|---|
| 0 | NOOP | NOOP | NOOP | NOOP |
| 1 | REANCHOR | NOOP | NOOP | NOOP |
| 2 | REANCHOR | NOOP | NOOP | NOOP |
| 3 | HARD | HARD | NOOP | NOOP |
| 4 | NOOP | NOOP | NOOP | SUSPECT |
| 5 | HARD | HARD | HARD | HARD |
| MOVED | REANCHOR | NOOP | NOOP | SUSPECT |
| MISSING | HARD | HARD | HARD | HARD |
| UNKNOWN | UNKNOWN | UNKNOWN | UNKNOWN | UNKNOWN |

`UNKNOWN` never demotes anything. Callers report it and leave the artifact's
state unchanged.

### G4. Bridge endpoints and bindings

*Fixes:* bridge refs are free strings with no snapshot binding, so they silently
dangle after re-ingest.

**Endpoint grammar:**

```
entity:<entity_id>
doc:<N> | doc:<N>#claim:<M> | doc:<N>#section:<M>
concept:<N>
root
```

where `N` and `M` are positive integers. `GraphCatalog.add_bridge` validates the
grammar and resolves each endpoint in the graph's *current* snapshot (code) or
paper database (papers). It rejects unresolved endpoints with `BRIDGE_ENDPOINT_UNRESOLVED`.

Each accepted bridge gets one `bridge_bindings` row per endpoint, recording:
- `graph_id`, `ref`, `snapshot_id` (code) or `paper_read_model` digest (papers);
- `entity_fingerprint_json`, a snapshot of the G2 fields for `entity:`
  endpoints, or `{"claim_text_sha256": …}` for claims.

Existing `root` bridges are bound to the graph's current `snapshot_id` with
empty fingerprints, and are never demoted by drift.

### G5. Staleness evaluation (`lineage-v1`)

*Fixes:* the CTE checked a single premise per clause, read stale states mid-sweep,
and had no defined fixpoint.

- **Artifacts:** an artifact `a` has a set of clauses `C(a)`. Each clause is a
  set of premises, and each premise is one of:
  - `(graph_id, ref, contract)` — ground;
  - `(artifact_id)` — upstream.
- **Ground premise value:** given the graph's new snapshot, a ground premise
  evaluates through G3 to `NOOP`, `REANCHOR`, `SUSPECT`, `HARD` or `UNKNOWN`.
- **Clause value:**
  - `HARD` if any premise is HARD;
  - else `SUSPECT` if any premise is SUSPECT, or any upstream premise is not
    `accepted`;
  - else `UNKNOWN` if any is UNKNOWN;
  - else `REANCHOR` if any is REANCHOR;
  - else `OK`.
- **Hop-1 state** (artifacts with at least one ground premise), from the best
  clause, where `OK > REANCHOR > UNKNOWN > SUSPECT > HARD`:

| Best clause value | New state |
|---|---|
| `OK` | `accepted` |
| `REANCHOR` | `provisional_reanchored` |
| `UNKNOWN` | unchanged |
| `SUSPECT` | `suspect_stale` |
| `HARD` | `demoted_contestable` |

- **Hop ≥ 2:**
  - An artifact whose premises are all upstream becomes `suspect_stale` iff
    every clause contains at least one upstream premise whose state (in this
    sweep's working map) is `suspect_stale` or `demoted_contestable`.
  - It returns to `accepted` iff some clause has all premises `accepted`.
  - It is never set to `demoted_contestable`.
- **Algorithm:**
  - Hop-1 first.
  - Then iterate hop ≥ 2 in ascending `artifact_id` order, recomputing until no
    state changes, capped at 8 passes.
  - All reads come from the working map, never from rows written earlier in the
    same sweep.
  - Write `artifact_states` and `revision_ledger` rows in one transaction.
- **Termination:** each pass is monotone over a finite lattice, and the cap is 8.

### G6. Directed contraction (`directed-helper-condensation-v1`)

*Fixes:* Phase 6 Theorem 3.1 is **false as stated**. Order-convexity of each
block does not make the quotient acyclic.

Counterexample: the DAG `a→b, c→d` with blocks `A={a,d}` and `B={b,c}`. Each
block is convex, yet the quotient has `A→B→A`.

- **Setting:** let `D` be the SCC condensation DAG of the filtered view, and `T⁺`
  the containment tree.
- **Correct construction (sequential convex contraction).** Process candidate
  blocks in canonical order of their representative ID. Maintain the current
  quotient DAG `Q` (initially `D`). Accept candidate `B` iff all four hold:
  - (I) `B` is convex in `Q`: no path leaves `B` and re-enters it, i.e. no
    `y ∉ B` with `x ⇝ y ⇝ z` for `x, z ∈ B`;
  - (II) every entry port reaches every exit port inside `Q[B]`;
  - (III) `B` lies inside one `T⁺` parent and excludes the protected spine
    (focus, its ancestors, pins, bridge endpoints);
  - (IV) `|B| ≥ 2`.
  
  If accepted, contract `B` in `Q`.
- **Theorem (replaces 3.1).**
  - If every accepted block satisfies (I) at its acceptance time, the final `Q`
    is a DAG, because contracting a convex vertex set of a DAG yields a DAG.
  - If additionally every block satisfies (II), then for every quotient path
    `B₀ → B₁ → … → B_m` there is a path in `D` from some member of `B₀` to some
    member of `B_m`. That path enters each intermediate `B_i` through an entry
    port and leaves through an exit port, so (II) supplies the inner segment.
- **Definition of `directed_reachability_preserved = true`:** quotient
  reachability between blocks implies *existential* member reachability in `D`,
  and every quotient arc has a witness relationship.
  - It does **not** claim all-pairs member reachability.
  - The envelope states this in `contraction.semantics = "existential_member_reachability"`.
- **Candidate generators** (cheap; each candidate is verified by I–IV):
  - single-entry dominator subtrees, depth ≤ 3. Use the Cooper–Harvey–Kennedy
    iterative dominator algorithm over a virtual source joined to every root of
    the `T⁺`-parent-induced subgraph, processed in reverse post-order;
  - single-exit post-dominator subtrees: the same algorithm on the reversed graph;
  - twins: members with identical external predecessor and successor sets.
- **Convexity check for `B` in `Q`:**
  - Compute `R⁺(B)`, the forward reachability from `B` restricted to vertices with
    `dag_rank ≤ max_rank(B)`.
  - Compute `R⁻(B)`, the backward reachability restricted to `dag_rank ≥ min_rank(B)`.
  - `B` is convex iff `(R⁺(B) ∩ R⁻(B)) \ B = ∅`.

### G7. Tier profiles and result limits

*Fixes:* the specs had one magic 1,800-token clamp and a 1M-token tier that could
not be delivered through the 8,000-char cap.

- **Profiles:** `profile ∈ {tier3_leaf, tier2_forager, tier1_lead}`.
  - The *ceilings* on `budget.limit_tokens` are 1,200 / 1,800 / 32,768.
  - A request above its profile ceiling fails with `BUDGET_EXCEEDS_PROFILE`; it
    is never silently clamped.
  - No profile means today's behaviour.
- **Librarian external-result limit** for a route with context window `W` tokens
  (`route_policy.context_tokens`, else `DEFAULT_CONTEXT_TOKENS = 131_072`):

  ```
  limit_chars(W) = 8_000                                   if W ≤ 131_072
                 = min(160_000, floor(W × 4 × 0.03))        otherwise
  ```

  A 1,048,576-token lead gets 125,829 chars, about 32k o200k tokens at the
  measured ≤ 4.15 chars/token. Results above the limit are still withheld intact,
  never clipped.

### G8. Graph lifecycle semantics

*Fixes:* the specs' delete would break FK and immutable rows, and could unlink
stores Geo-Grapher doesn't own.

- **Owned store:** `code_database` lies under
  `<catalog_dir>/graphs/<graph_id>/`. Everything else is *registered* and is
  never unlinked.
- **copy(graph_id, label):**
  - online `sqlite3.Connection.backup` into `graphs/<new_id>/code.sqlite`;
  - `new_id = 'g_' + digest('copy-v1', source_id, label, source_snapshot_id)[:24]`;
  - `root_key = 'copy:' + new_id`;
  - profile `{graph_kind: 'copy', copied_from: source_id, owner_repo_ids: <source owners>}`.
  - Repo IDs inside the store are unchanged, so ownership checks pass.
  - Paper databases are not copied (`paper_database = NULL`).
- **delete(graph_id)** refuses with `GRAPH_IN_USE` if:
  - any `merge_receipts.graph_id` equals it;
  - any graph's profile lists it in `source_graphs`;
  - or it is the hub's `primary_graph_id`.

  Otherwise, in order:
  1. Retire all router keys for it and wait for leases to reach 0 (timeout 10 s
     → `GRAPH_BUSY`).
  2. In one catalog transaction: delete its `bridges` rows (returned in the
     receipt), `overlap_decisions` rows and `graphs` row.
  3. For owned stores only: `PRAGMA wal_checkpoint(TRUNCATE)`, close, `gc.collect()`,
     then unlink `code.sqlite`, `-wal` and `-shm` with 5 retries (backoff 50 ms ×

### G14. Affinity-aware sibling layout (`sphere-affinity-v1`)

*Fixes:* "position is not similarity". The layout is pure Python (`math` only,
D1). It is a **new** `layout_version`; `sphere-pack-v1` stays byte-identical, so
existing layout tests, digests and saved layout edits remain valid. The frontend
requests `sphere-affinity-v1` by default.

**Inputs per parent `P`:**
- the sibling IDs `S` (sorted) and their radii;
- affinity `A[u][v] = A[v][u]`, the sum of `witness_count` over the frame's
  quotient projections between `u` and `v` in either direction, plus the
  documentary link `incidence_count` between them;
- external degree `x(u)`, the summed `witness_count` of projections from `u` to
  reps outside `P`'s subtree.

**Coreness and bands:**
- `d(u) = Σ_v A[u][v]`.
- `c(u) = ln(1+d(u)) + 0.5·ln(1+x(u))`.
- `ĉ(u) = c(u)/max_S c`, or 0 if the max is 0.
- `r_norm(u)`:

  | Band | Condition | r_norm(u) |
  |---|---|---|
  | crust | `d(u) = 0` | `0.95 − 0.23·ĉ(u)` ∈ [0.72, 0.95] |
  | core | `ĉ(u) ≥ 0.66` | `0.42 − 0.37·(ĉ(u)−0.66)/0.34` ∈ [0.05, 0.42] |
  | mantle | otherwise | `0.72 − 0.30·ĉ(u)/0.66` ∈ [0.42, 0.72] |

- Target distance from `P`'s centre: `ρ(u) = r_norm(u) · max(0, R_P − PADDING − r_u)`.
  `R_P` is computed as in `pack_siblings` today. The affinity layout then uses
  `R_P_aff = 1.15 · R_P` *(amended at the wave 1 gate: on real graphs, tight
  packing erased angular structure)*.

**Directions:**
- Seed with the existing golden spiral over `S` sorted by `(−ĉ, id)`, with the
  phase from the existing seed digest.
- Run **40** Jacobi steps `k = 0…39`: compute all updates from the previous
  directions, then apply them together. With `η = 0.15·(1 − k/40)`:

  ```
  F(u) = Σ_{v: A>0} w(u,v)·(x̂_v − x̂_u) − Σ_{v: A=0} (0.5/|S|)·(x̂_v − x̂_u)/max(1e-6, |x̂_v − x̂_u|²)
  w(u,v) = max(0.25, A[u][v] / max_S d)          (amended at the wave 1 gate: floor for weak pairs)
  F_t(u) = F(u) − (F(u)·x̂_u)·x̂_u                   (tangent-plane projection)
  x̂_u ← unit(x̂_u + η·F_t(u))
  ```

  If `x̂_u + η·F_t(u)` has norm < 1e-12, keep `x̂_u`.
- **Cost bound:** skip relaxation, keeping the seeds, when
  `40·|S|·(|S|−1)/2 > 2,000,000` (|S| ≳ 316).
- Initial centres are `x̂_u · ρ(u)`.

**Collision and containment:** use the existing pairwise solver and containment
clamp, with one change. A pair's overlap shift is split by mobility
`m(u) = 1/(1+3ĉ(u))`: `u` moves `shift·m(u)/(m(u)+m(v))`, so core hubs stay near
the centre. On failure, use the existing `compact_fallback`.

**Determinism:** sort everything by ID, run fixed steps, and round final centres
with `round(x, 9)`. Input order of the IDs must not change the output.

**Quality checks** (each asserted on a fixture; measured on ToolSet in the gate):
- 0 overlaps and 0 containment breaches (existing `violations ≤ EPS`);
- mean `r_norm` ordered core < mantle < crust;
- mean cosine between directions of affine pairs > mean cosine of zero-affinity
  pairs.
