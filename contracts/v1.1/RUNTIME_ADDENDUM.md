# P5.4 runtime observations

The original SQLite DDL and v1.0 wire remain unchanged. Runtime facts use the existing `runtime` family, `observed` status, `dynamic_observed` evidence and `call_count` unit. They never overwrite static conclusions, documentary assertions or review decisions.

## Import contract and publication

`geographer ingest-trace --database DB --snapshot-id BASE --trace calls.jsonl` reads a completed base snapshot and the sidecar `calls.jsonl.manifest.json`. `--manifest FILE` selects another sidecar. Optional `--environment`, `--start` and `--end` must agree with it; `--report FILE` archives the import report. The Python API is `trace.ingest_trace(store, base_snapshot_id, raw_bytes, manifest, *, environment=None, start=None, end=None)`.

`geographer.trace.schema.json` defines strict `Manifest` and `CallRecord` records. JSONL is UTF-8; duplicate JSON keys, duplicate raw records and duplicate normalized caller/line/callee sites are rejected. Required row fields are `caller_path`, `caller_qualname`, `caller_line`, `callee_path`, `callee_qualname`, and positive integer `call_count`. Optional fields identify caller/callee repo namespaces, callee definition line, activation kind and producer-reported finite nonnegative `p95_ms`. Counts and their collection sum stay within the exact integer range `2^53-1`. Import never computes an average/global p95.

Manifest fields identify format `python-call-trace-v1`, environment, UTC window, every source repository's revision/digest, explicit root mappings, recorder/version/backend/build, declared process/thread/async coverage, source match and SHA-256 of the raw trace. Recorder statistics, exit status and command digest are optional. `source_match=false`, checksum mismatch, source-manifest mismatch, contradictory complete/truncated coverage and invalid timestamps are rejected. Timestamps use ISO UTC `Z` with at most six fractional digits and normalize to six digits; end must exceed start.

Operational limits: trace 64 MiB, manifest 1 MiB, 100,000 records, 16 KiB per record and 256 inherited collections per snapshot. Quarantine retains at most 1,000 records/1 MiB of samples, with complete reason/record/call totals and an explicit sample-completeness flag. Input call counts reconcile as mapped plus quarantined counts.

Mapping uses repository/path plus exact CPython `co_qualname` or canonical file-qualified name. Nested `.<locals>.` components normalize to the canonical lexical name. `<module>` maps to the file body; classes/functions/methods use their source definitions. Caller line ranges and optional callee definition/decorator-start lines disambiguate repeated definitions. Explicit namespaces disambiguate repositories; unresolved alternatives are quarantined. Windows root/path comparison respects case-insensitive paths while identifiers stay case-sensitive. Absolute paths must be lexically within supplied roots; relative traversal is rejected. The importer reads stored snapshot bytes, never files named by trace rows, and never executes input code.

External manifests are producer assertions: matching declared hashes does not independently attest that their reported execution occurred. The built-in recorder additionally verifies cached snapshot bytes against repository digests and local source before/after execution. Neither path claims immunity to arbitrary runtime code fabrication or monkeypatching.

Publication uses a single `BEGIN IMMEDIATE` transaction. It creates a new content-addressed child manifest containing parent ID, collection ID and mapper build/version; copies canonical source/static/runtime facts and selected source/static/collection metadata; appends normalized observed relationships/evidence; regenerates standard static rollups for Stage 2+ bases; runs full publication validation; then marks complete and commits. Failure rolls back the entire child. Canonical IDs, ownership/lifting, source revisions/digests, AST/WL values and prior facts remain unchanged. Query handles, layouts and review overlays are not copied across snapshots.

The same collection imported on its base returns the existing child; importing it on a descendant already containing it returns that descendant. Distinct overlapping windows in one environment cannot be combined in a snapshot; conflicting artifacts are rejected. There is no automatic merge/replacement or quantile merge. Different snapshots can represent separate branches; their counts are not automatically summed. New mapping implementations carry a build digest rather than silently modifying published evidence.

Each observed row retains its original record and collection reference in lazy evidence. Static comparison distinguishes matching exact/candidate targets, a different observed target on a line with exact static targets, and no matching static target. Comparison is at source-line precision: this input format has no column data, and multiple syntax occurrences can share a line. It does not map counts to a unique AST occurrence, promote candidates, downgrade static facts or establish whole-path execution. Static-only cached diagnostics remain static; runtime projections use the selected window/environment.

## Explicit recording and pytest

```text
geographer record-trace --database DB --snapshot-id BASE 
  --repo-root repo_id=LOCAL_ROOT --environment dev --output calls.jsonl 
  -- python -m application
```

Repeat `--repo-root` for every snapshot repository; recorder roots must be disjoint. The supplied Python interpreter runs a standalone stdlib wrapper without shell interpolation. Supported targets are scripts, `-m MODULE`, `-c PROGRAM` and interpreter flags `-u/-B/-I/-E/-s/-S`. Recording is opt-in execution; ordinary repository/trace ingestion never runs application code. Indexed source cannot be overwritten by a trace destination. Artifact publication uses unique temporary files and checksums; interrupted trace/manifest pairs fail import rather than appearing valid.

`sys.setprofile` is the implemented backend, tested on Python 3.11.3. The optional Python 3.12+ `sys.monitoring` backend is not enabled or claimed tested. A recorder build digest, interpreter version, coverage and limits accompany each artifact.

Default capture limits are 60 seconds, 100,000 logical call activations and 64 MiB; configurable maxima are 3,600 seconds/1,000,000 activations/64 MiB, with microsecond minimum duration and 1,024-byte minimum byte limit. Unique records cap at 100,000 and retained live frames at 10,000. Duration limits bound recording, not command duration: the application can continue after capture stops. Truncation/unknown dropped counts are explicit. Hook replacement, field limits, source changes and crashes cannot masquerade as complete capture.

The main and newly started Python threads are covered until the invoked Python entrypoint returns; pre-existing threads, subprocesses, interpreter shutdown and trailing thread work are excluded. The pytest plugin ends capture at sessionfinish. PID guards prevent forked children from publishing the parent's capture. Only indexed Python filenames under the configured roots are eligible callees; unindexed virtual environments are not silently included. First generator/coroutine/async-generator activation is counted once; resume segments are tracked separately, not counted as repeated logical calls. This is first activation, not coroutine-object creation or reconstructed task causality. Module/class definition frames and recorder implementation are excluded as callees; module/class bodies remain supported callers. Python frame adjacency can omit native intermediates. No latency quantile or wall-duration p95 is fabricated from segments.

Exit status is preserved. Normal failure retains positive observations with incomplete-run coverage. On parent console interruption, the wrapper allows the child to finalize before terminating an unresponsive child. A hard child exit without finalized artifacts produces an empty, source-unverified failed capture that cannot be ingested as matching telemetry. Forced termination of the recorder parent cannot guarantee artifact finalization. Prior main/thread profile hooks are restored; no automatic plugin entry point installs recording.

Pytest can run through `record-trace -- python -m pytest ...`, or explicitly load `-p geographer.pytest_trace` with `--geographer-trace-output`, `--geographer-trace-database`, `--geographer-trace-snapshot`, repeated `--geographer-trace-root ID=PATH`, and optional environment/limit flags. The plugin verifies sources before tests, records through `sessionfinish`, restores hooks and publishes the same format. Loading it without an output option does not start profiling. On Windows cross-drive fixture runs, specify pytest's `--rootdir` explicitly. Executed-line coverage does not imply call edges; no coverage-to-call inference is implemented.

## Shared service and workspace

The existing seven MCP tools remain read-only. Collection discovery is available through `geographer://runtime-collections/{snapshot_id}` and its advertised resource template. It returns windows, declared coverage/counts and lazy report handles; full quarantine samples are fetched explicitly through a handle resource. These resource reads are not falsely advertised as token-packed query envelopes. Ordinary query responses retain final exact/byte-bound accounting.

Bootstrap exposes collection summaries and source-match/capture state. A matching collection with zero mapped facts remains selectable/queryable; it does not prove absence. Unknown windows/environments fail explicitly. Runtime filters require an exact collection window/environment; observations from other collections are excluded. Legacy observed facts without catalog records remain readable when their evidence matches the requested window.

The workspace enables Runtime overlay only with a matching collection, adds `observed` alongside selected static statuses, supports window/environment selection, and restores the static filter when disabled. Switching to source-only snapshots clears stale runtime scope; saved collection views validate snapshot/window availability before restore. Coverage responses are guarded against stale selection changes. Matrix/Inspector retain witnesses, call counts and units separately; static and runtime weights are never blindly added. Sage curves render actual observed relationships with the same deterministic parallel lanes. Captures say what was observed within their declared scope; non-observation is not absence or a complete execution proof.
