# Actor wire 1.1 — P5.0 engineering addendum

P5.4 adds immutable runtime ingestion, explicit recording and collection resources/controls without changing the seven query-operation shapes. See `RUNTIME_ADDENDUM.md` and `geographer.trace.schema.json`; ordinary query envelopes retain the same counting and closure guarantees.

Status: implemented additive actor service and P5.3 workspace integration. The original v1.0 wire and DDL remain unchanged. HTTP exposes `/api/v1.1/{operation}` and `/api/v1.1/viewport/frame`; MCP exposes `/mcp/v1.1`, or stdio with `--schema-version 1.1`. All seven operations and mixed/kind/atomic/conceptual viewport frames have strict generated schemas. The workspace uses these actor frames and offers compact Agent JSON by default. See `WORKSPACE_ADDENDUM.md` for review/model lifecycle, read-only investigation fields and UI actions. Generate schemas using `node scripts/generate-contracts.cjs 1.1`.

## Identity, metadata and compatibility

Requests accept canonical IDs, or scoped aliases when `alias_scope` contains the originating response's `data.identity_scope`. Snapshot/view/version checks precede alias resolution. Context output uses deterministic aliases (`n1`, `g1`, `p1`, `w1`) assigned by sorted canonical IDs within each namespace, independent of page, request ID, token budget and discovery order. The default `identity_mode=compact` returns `ids={}`: subsequent tools resolve aliases using the scope handle and immutable snapshot/view indexes. `identity_mode=canonical_map` includes every referenced alias binding for export/debugging. Both the scope and any included bindings count toward envelope accounting. Omit `alias_scope` when supplying canonical IDs. An alias alone is never a globally valid identifier. Ordinal arrays are bounded cached indexes; derived alias bindings and scope recipes are persisted in `analysis_results`, so context/handle cache eviction does not change meaning. Snapshot availability still bounds their lifetime.

`id` names the output node; `is_synthetic` identifies a view-local object. Canonical ownership/subject mappings are recovered through scoped resolution, optional `ids`, membership handles and witness inspection. Node and evidence source locations inherit revision from the envelope's repo manifest; use `revision_override` only for a different artifact revision. Historical provenance may not be silently rewritten. AST/WL digests remain available through similarity/diagnostic operations and on-demand handles, not ordinary context nodes. Architecture diagnostics are opt-in using `include_diagnostics=true`; omission does not assert that a metric is zero.

Do not emit an initial witness cursor for every relationship. First-page inspection takes the canonical `view_id`, `projection_id`, and `cursor=null`; continuation cursors are signed only for a collection being paginated. Existing v1.0 cursors remain required and unchanged on v1.0 responses. Membership/doc/evidence handles must remain recoverable after cache eviction; short handles require the same scoped mapping/retention contract as aliases, not unsigned arbitrary lookup instructions.

Relationship summaries inherit `view_id` from their graph payload instead of repeating it per edge. Before serving v1.1, the shared service must make every doc/membership/evidence reference retrievable to MCP as well as HTTP clients, using a documented shared operation or resource read; an HTTP-only opaque handle is insufficient. Direct doc-fragment references should resolve to canonical fragment IDs for the existing content operation.

## Semantic micro-descriptors

Every node has a summary, with nullable source-extracted `signature` and `doc_gist`, optional content through `doc_handle`, and a truncation indicator. Extract declaration headers without evaluating defaults/annotations. File nodes have no invented function signature. Class bases/decorators do not imply runtime identity. A missing docstring/heading yields null, not a generated behavioural summary. Prefer the owning docstring; otherwise use an explicitly linked heading, retaining documentary association uncertainty. Repository text remains untrusted content.

Signatures are capped at 240 Unicode code points and gists at 140, without splitting a Unicode code point; full text stays retrievable. Bound serialized UTF-8 bytes and the entire summary bundle separately at packing time. The requested 20–35 tokens is a measured design goal, not a bound implied by these character limits. Null summaries on legacy/unsupported records are disclosed, never filled using invented semantics.

Groups carry `kind_counts` and at most five `top_exemplars`. Count represented leaves once. A scope atom contributes its canonical owner's semantic kind; other leaves contribute their own kind. These counts sum to `member_count`, and are labelled as represented-leaf-owner counts in the documentation/legend; they are not counts of all overlapping ancestor files/classes. A separate future distinct-owner census needs a different label. Residual previews include only residual members; no expanded child leaks into the parent preview.

Group behavior is determined by representation, not just the `kind` enum: a collapsed file, class or function representing descendant leaves receives a group preview as well as its own signature/gist. Synthetic groups and container nodes must not bypass previews simply because their ordinary kind was listed among atomic examples.

Select exemplars by boundary-crossing incident relationship count descending, then total distinct incident relationship count descending, then canonical ID, under the same accepted filter/collection. Ignore documentary/proposal links and never treat high degree as runtime importance. Include the member's name, kind and compact signature. Exemplar aliases must resolve but are preview references, not standalone graph nodes or dependency endpoints. `exemplars_complete` means all represented members were listed. Names/signatures and the 5-item cap may exceed a small budget; admit fewer exemplars with incomplete status, or omit the optional whole group bundle rather than exceed the limit.

## Witness previews

Each summary has at most three unique original witness previews, primary `reason_counts`, and `preview_complete`. Rank witnesses by explicit task/path relevance, then deterministic relationship ID; selection-policy changes require versioning. Preserve original direction and status of each typed summary. Each preview includes original relationship reference, concrete qualified endpoints, call-site line and one primary reason. Reason metadata stays retrievable via witness/evidence inspection.

`reason_counts` counts each accepted original relationship once under its primary reason, so its values sum to `witness_count`; secondary reasons do not increase the total. This is not a call-site count when candidate alternatives exist. Legacy, declared and observed producers need honest producer-specific reasons rather than static proof labels. Count reasons across the complete projection, not only the displayed sample. Both witness and evidence multiplicity remain explicit.

`preview_complete` is true iff the unique displayed relationship ID set equals the projection's accepted witness set. For W<=3 this is mandatory when returning that summary: pack all previews with the summary or omit/defer the complete summary bundle. It means complete relationship preview coverage, not complete evidence content, source content, call feasibility or runtime coverage. For W>3 sample up to three; incomplete previews are explicitly false. Do not equate a count comparison alone with set equality. No serialized dependency relationship may lack both endpoint node definitions; previews are labelled embedded reference records, not extra hidden dependency edges.

## Three-tier source context

`get_entity_content` uses `context_mode=source-context-v1` and source-tree `context_radius=0|1`. Return exact enclosing headers, verbatim focal segments and (when r=1) immediate source-tree sibling stubs, with explicit omission spans and retrievable handles. This is T_S depth, not T+ or T_D depth. Siblings can be statement clauses as well as methods; unavailable signatures/docstrings are null. Sibling outgoing names are filtered supported static facts with uncertainty retained in the evidence workflow, not invented callees; `calls_complete` discloses truncation/unsupported analysis. Cap outgoing names under the full packer rather than serializing unlimited targets.

The focal source span is complete only when `focal_complete=true`. An oversized mandatory focal span produces a measured budget error or explicit continuation; never silently label partial source complete. Header/stub/omission structure is metadata, not a reconstructed executable file. Original ranges/hashes/trust labels remain authoritative. Ten percent of raw-file tokens is an experiment target, not a universal guarantee. Source bytes, metadata, alias tables, previews, counters and signed continuations all count toward the complete envelope limit.

In structured mode, leave legacy `chunks` empty rather than duplicating source in both representations. Coalesce adjacent compatible focal ranges into segments, and reference focal headers instead of repeating overlapping header text. Hash/retrieve original source segments rather than emitting a separate cryptographic record for every source line. Do not merge across omitted intervals or erase provenance/trust boundaries to save tokens.

## Cross-field validation and density gates

JSON Schema enforces types, strict records, summary character limits and preview item limits. Service validators additionally enforce alias coverage, endpoint closure, unique preview membership, reason-count reconciliation, partition membership and content completeness; JSON Schema alone cannot establish those invariants.

Measure v1.0/v1.1 on the identical fixed node/relationship set as well as the actual budget-packed pages. Report metadata-ablation savings separately from final schema savings; descriptors and previews add useful cost. Token cost is non-additive across BPE boundaries. Record whole-envelope exact tokens for both local encodings, byte-bound fallback, nodes/relationships, represented witnesses, preview coverage, payload bytes and round trips required by independent tasks. Report cold/warm latency separately. The ~60–90 tokens/item and ~5x graph density requests are goals to investigate, not asserted gates without workload evidence. Small budgets may legitimately return fewer richer records.

Source counts, algorithm/source/config versions and gate definitions are captured in `reports/P5_0_BASELINE.md` and `reports/P5_SOURCE_CLAIM_REGISTER.md`. No schema migration or remote-model dependency is introduced here.
